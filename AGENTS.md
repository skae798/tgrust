# Инструкции для агентов tgrust

## Цель и статус

Развивайте неофициальный клиент Telegram на Rust для GNOME/Wayland. Проверяйте заявленные возможности по коду и тестам. Обновляйте README, когда меняются запуск, зависимости, ограничения или список возможностей.

## Код

- Держите виджеты GTK и состояние UI в основном потоке GLib. Выполняйте сетевые запросы и загрузки в Tokio. Передавайте в UI модели из `src/model.rs`.
- Используйте grammers и типы Telegram для работы с MTProto. При обновлении grammers проверьте вместе версии всех его пакетов и изменение схемы Telegram.
- При переключении чатов проверяйте, что ответы на старые запросы попадают в правильный чат. Сохраняйте черновики и предотвращайте дубли сообщений.
- Для загрузок используйте выбранный пользователем локальный путь, временный файл в том же каталоге и завершение без перезаписи. Имя из Telegram служит только предложением для диалога сохранения.
- Соблюдайте отдельные ограничения на самоуничтожающиеся сообщения. Загрузки используют обычную авторизацию аккаунта и данные сообщения, доступного этому аккаунту.
- Сохраняйте поведение частной сборки в отношении спонсорских сообщений и ручного сохранения доступных вложений. При изменениях этих возможностей обновляйте описание ограничений API в README.
- Оставляйте интерфейс пригодным для клавиатуры и узких окон. Используйте стандартные компоненты Libadwaita и системные цвета.

## Сессии и проверки

- Не коммитьте номера, коды входа, облачные пароли, API-хеши, файлы сессии и переписку. Используйте вымышленные данные в деморежиме, тестах, логах и скриншотах.
- Перед отправкой коммита выполните `cargo fmt --all -- --check`, `cargo clippy --locked --all-targets -- -D warnings`, `cargo test --locked` и `git diff --check`.
- Изменения интерфейса проверяйте с `cargo run --locked -- --demo`. Для сетевых изменений отдельно фиксируйте, что проверено на тестовом аккаунте. Автоматические проверки не требуют Telegram-аккаунта.
- Сохраняйте `Cargo.lock` в репозитории. Обновляйте его вместе с изменениями зависимостей.

## GitHub

- Репозиторий `skae798/tgrust` приватный. Сохраняйте его видимость, пока владелец явно не запросит изменение.
- Для отдельной задачи используйте короткую ветку от `main`. В PR указывайте проверенные сценарии и оставшиеся ограничения. Связывайте PR с задачей, если она есть.
- Держите `main` в состоянии, пригодном для сборки. Не переписывайте опубликованную историю.
