# tgrust

Неофициальный настольный клиент Telegram для GNOME. tgrust использует Telegram API через [grammers](https://codeberg.org/Lonami/grammers). Приложение написано на Rust с GTK 4 и Libadwaita и распространяется по GPL-3.0. Исходный код Telegram Desktop в проекте не используется.

## Возможности первой версии

- Адаптивный интерфейс GNOME с системной темой, акцентным цветом и списком чатов с поиском по названию.
- Вход в существующий аккаунт по номеру, коду и облачному паролю. Локальная сессия позволяет запускать клиент повторно.
- Последние 150 диалогов, история с постраничной загрузкой, отправка текста в личных чатах и группах. При открытии чата можно сразу писать. Enter отправляет сообщение, Shift+Enter добавляет новую строку. История обновляется при получении событий Telegram.
- Отправка одного локального файла или фотографии с подписью через меню вложений. Режим «Файл» сохраняет исходные байты, режим «Фотография» использует обработку изображений Telegram. Сервер применяет ограничения аккаунта и чата.
- Ответы в текущем чате с карточкой цитаты. Нажатие на карточку открывает исходное сообщение. Клиент загружает цитаты за пределами текущей страницы, если они доступны.
- Редактирование своих обычных текстовых сообщений без форматирования. Telegram определяет срок и права для правки.
- Удаление своих сообщений для всех участников чата после подтверждения. Действуют права и ограничения Telegram.
- Удаление сообщений из «Избранного», включая сохранённые пересылки. В «Избранном» удаляется сохранённая копия.
- Пересылка одного сообщения в доступный чат из списка. Telegram применяет ограничения на пересылку защищённых и самоуничтожающихся сообщений.
- Закрепление и открепление сообщений без уведомления участников. Закреплённые сообщения отмечаются в загруженной истории, права проверяет Telegram.
- Обычные эмодзи-реакции в истории с количеством и отметкой своей реакции. Эмодзи можно выбрать в контекстном меню. Доступный набор и число реакций определяет Telegram.
- Глобальный поиск по тексту сообщений с переходом к найденному сообщению. За запрос показываются до 50 доступных результатов Telegram.
- Архив чатов с переключением списка и возвратом чата из архива. Показываются архивные чаты из загруженных диалогов.
- Уведомления GNOME о новых сообщениях при запущенном клиенте. Нажатие открывает чат из загруженных диалогов. Уведомление показывает название чата, учитывает отключение звука для чата и категории и исключает сообщения с таймером. Открытый активный чат обновляется без уведомления.
- Просмотр папок, настроенных в Telegram, включая импортированные общие папки. Фильтры и закрепления папки применяются к загруженным диалогам.
- Спонсорские сообщения Telegram не запрашиваются и не отображаются.
- Документы и фотографии можно сохранить через системный диалог, в том числе из чатов с запретом на сохранение. Загрузка требует доступа к сообщению и файлу на сервере. При истечении ссылки клиент один раз заново запрашивает сообщение и повторяет загрузку того же файла. Сохранение самоуничтожающихся сообщений и вложений с таймером отключено.
- Крупные миниатюры без подписи интерфейса. Фотографии открываются в отдельном окне по нажатию на изображение или через контекстное меню. Клиент использует доступную версию изображения размером до 1600 × 1600 и держит её в памяти. Фотографии с таймером исключены.
- Имена и аватарки авторов входящих и исходящих сообщений. В списке групповых чатов рядом с последним сообщением отображается @ник автора или имя. Когда фото профиля недоступно, отображаются инициалы. У фотографий и документов с серверной миниатюрой есть изображение в истории. Вложения со спойлером и таймером не показывают миниатюру автоматически.
- Деморежим с вымышленными чатами, локальной отправкой сообщений, имитацией отправки вложений и скачиваемым тестовым файлом. Подключение к Telegram для деморежима не требуется.

У Telegram есть требования к показу спонсорских сообщений и обработке запретов на сохранение. С этими настройками Telegram может отключить доступ приложения к API. См. [условия Telegram API](https://core.telegram.org/api/terms) и [правила защиты контента](https://core.telegram.org/api/content-protection).

## Сборка на Fedora

Понадобятся Rust 1.100.0 или новее, GTK 4.16 и Libadwaita 1.6 или новее. Для сборки встроенной базы сессий требуются CMake и libclang.

```sh
sudo dnf install gcc make cmake clang-devel pkgconf-pkg-config gtk4-devel libadwaita-devel
rustup update stable
cargo build --locked
cargo run --locked -- --demo
```

### Вход в аккаунт

Создайте приложение на [my.telegram.org](https://my.telegram.org/apps) и получите `api_id` и `api_hash`. Запустите клиент из Bash, передав значения через окружение. При скрытом вводе хеш не попадёт в историю команд.

```bash
read -rp 'API ID: ' TGRUST_API_ID
read -rsp 'API hash: ' TGRUST_API_HASH
printf '\n'
TGRUST_API_ID="$TGRUST_API_ID" TGRUST_API_HASH="$TGRUST_API_HASH" cargo run --locked
unset TGRUST_API_ID TGRUST_API_HASH
```

Введите номер в международном формате, затем код и, если Telegram запросит, облачный пароль. При следующем запуске tgrust автоматически подключится, если сохранена одна действующая сессия. Если Telegram недоступен, восстановите сеть и нажмите «Повторить подключение». Для повторного входа после истечения сессии снова передайте ключи приложения.

Сессия находится в `${XDG_DATA_HOME:-$HOME/.local/share}/tgrust/<api_id>.session`. tgrust открывает её в одном экземпляре приложения и задаёт права `0600` для новых и существующих файлов сессии. Каталог сессии доступен только владельцу. Файл содержит ключ авторизации и даёт доступ к аккаунту. Храните его локально.

### Установка и обновление из GitHub

Установите зависимости сборки, Git, `util-linux` и `desktop-file-utils`. Репозиторий можно скачать без входа в GitHub.

```sh
git clone https://github.com/skae798/tgrust.git
cd tgrust
./scripts/update.sh
```

Запускайте тот же скрипт для обновления. Он скачивает актуальный коммит ветки `main`, собирает клиент с `Cargo.lock` и устанавливает бинарник в `~/.local/bin/tgrust`, а ярлык и значок — в каталог данных пользователя. Исходники загружаются в отдельный кэш. Установка начинается после успешной сборки. При открытом клиенте перезапустите его после обновления.

Ярлык tgrust появится в меню GNOME. Чтобы закрепить его в доке, выберите «Добавить в избранное». При запуске из меню или дока клиент использует сохранённую сессию.

## Устройство проекта

| Файл | Назначение |
| --- | --- |
| `src/main.rs` | Запуск приложения, параметры и завершение работы |
| `src/ui.rs`, `src/style.css` | Интерфейс Libadwaita и обмен данными с Tokio |
| `src/telegram.rs` | Сессия, авторизация, диалоги, история, обновления и загрузки |
| `src/storage.rs` | Каталог сессии и имена файлов из сети |
| `src/model.rs`, `src/demo.rs` | Модели интерфейса и демоданные |

## Проверки

```sh
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
cargo run --locked -- --demo
```

В деморежиме проверьте поиск чата, переходы в узком окне, отправку текста и сохранение файла `заметки.txt`. Для проверки Telegram используйте тестовый аккаунт и чат, которым вы управляете. Проверьте вход и повторное открытие сессии, обмен сообщениями с другим клиентом и сохранение своих файлов из обычного и защищённого чата.

Для проверки уведомлений запустите установленное приложение с тестовой сессией в GNOME. Сверните окно и отправьте сообщение со второго клиента. Нажмите на системное уведомление и убедитесь, что открылся нужный чат. Повторите при активном чате и с выключенными уведомлениями для чата. В этих случаях уведомление не должно появляться.

Для проверки восстановления входа запустите клиент с отключённой сетью и уже сохранённой тестовой сессией. Восстановите сеть и нажмите «Повторить подключение». Список чатов должен открыться без нового кода. При первом входе с двухэтапной аутентификацией проверьте повторный ввод после неверного пароля и повторный запрос кода после сбоя проверки пароля.

После входа tgrust повторяет подключение при временной ошибке потока обновлений. Чтобы проверить этот сценарий, откройте тестовый чат, отключите сеть только на машине с tgrust, отправьте сообщение и измените его со второго клиента. Восстановите сеть, оставив tgrust открытым. Проверьте появление сообщения и его последней версии в истории, затем отправьте ещё одно сообщение со второго клиента и проверьте, что оно приходит автоматически.

Для проверки истории добавьте в тестовый чат больше 40 сообщений. Загрузите старую страницу и одновременно отправьте новое сообщение со второго клиента. Оно должно появиться без ручного обновления. Затем отключите сеть tgrust, добавьте со второго клиента больше 40 сообщений и восстановите сеть. Откройте старые сообщения через кнопку истории и проверьте, что между страницами нет пропусков. Во время отправки переключитесь в другой чат и обратно. Проверьте, что отправленное сообщение появилось один раз, а черновики других чатов сохранились.

Для проверки загрузки отправьте в управляемый тестовый чат фото и документ размером от 12 МиБ. Сохраните их через tgrust, сравните размер и SHA-256 документа с оригиналом и откройте фото. Повторите сохранение при включённом запрете на сохранение и с уже существующим файлом назначения. Сравните SHA-256 существующего файла до и после попытки. Если сервер вернёт `FILE_REFERENCE_EXPIRED` или `FILE_REFERENCE_INVALID` во время передачи, клиент должен получить актуальную ссылку и заново скачать те же байты. При недоступности сообщения или файла диалог сообщит об ошибке, а временный файл будет удалён.

Для проверки отправки добавьте файл в тестовом чате, переключитесь в другой чат и вернитесь. Проверьте имя и подпись в черновике. Отправьте файл и сравните SHA-256 с оригиналом на втором клиенте. Отправьте JPEG через пункт «Фотография» и проверьте отображение фотографии и подписи. При отказе сервера имя вложения и подпись должны оставаться доступны для повторной отправки.

Открывайте действия с сообщением правой кнопкой мыши. С клавиатуры выберите сообщение через Tab, затем нажмите Shift+F10 или клавишу Menu. Для проверки ответов выберите «Ответить» в этом меню. Отправьте ответ и проверьте на втором клиенте связь с исходным сообщением. Повторите с вложением и проверьте отмену ответа до отправки.

Для проверки правок отправьте обычный текст в тестовом чате и выберите «Редактировать». Сохраните новый текст и проверьте метку «Изменено» на обоих клиентах. Проверьте, что закрытие редактора без сохранения оставляет исходное сообщение и черновик нового сообщения.

Для проверки удаления отправьте тестовое сообщение, откройте диалог удаления и отмените действие. Убедитесь, что сообщение осталось в истории. Затем подтвердите удаление и проверьте, что оно исчезло на обоих клиентах и из последнего сообщения в списке чатов.

Для проверки пересылки выберите «Переслать» у обычного сообщения и выберите другой тестовый чат. Откройте его на втором клиенте и проверьте, что сообщение пришло один раз с отметкой о пересылке. Повторите с защищённым сообщением и проверьте, что пересылка недоступна или отклонена сервером.

Для проверки закреплений выберите «Закрепить» у сообщения в тестовом чате с подходящими правами и проверьте отметку на двух клиентах. Открепите сообщение со второго клиента и убедитесь, что отметка пропала из открытой истории.

Для проверки реакций добавьте обычный эмодзи в тестовом чате, сверяйте количество на двух клиентах и снимите свою реакцию повторным выбором эмодзи в меню. Если аккаунт поддерживает несколько реакций, поставьте две со второго клиента и снимите одну в tgrust. Вторая должна сохраниться.

Для проверки поиска отправьте редкую фразу в двух тестовых чатах. Найдите её через «Поиск по сообщениям», откройте результат старше первой страницы и убедитесь, что исходное сообщение выделено среди соседних. Нажмите «К последним сообщениям» для возврата в конец истории.

Для проверки предпросмотра откройте «Пробный кадр» в деморежиме. В тестовом чате откройте обычную фотографию и фотографию со спойлером, для которой просмотр должен начаться после нажатия. У фотографии с таймером кнопка предпросмотра отсутствует.

Для проверки аватарок и миниатюр откройте тестовый диалог и группу с фото профиля, отправьте фотографию и видео с обложкой, затем переключитесь между чатами. В истории должны остаться миниатюры и аватарки соответствующих сообщений. Для участника без фото проверьте инициалы.

Для проверки архива переместите тестовый чат через кнопку в заголовке. Проверьте, что чат виден при включённом «Архиве чатов». Верните чат из архива и проверьте перемещение в обоих направлениях на втором клиенте.

Для проверки папок настройте на втором клиенте папку с явным включением и исключением чатов, закреплённым чатом и фильтром по типу. Выберите папку в tgrust и сравните состав и порядок среди загруженных диалогов. Измените папку со второго клиента и проверьте обновление списка.
